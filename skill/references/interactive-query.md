# 交互追问 - Interactive Query

## 用途
本文件定义了用户完成初始分析后，进行追问的处理方法。Codex 在 Phase 5 处理用户追问时加载本文件。

## 通用原则
- 追问必须基于已产生的分析内容，不能编造不一致的结论
- 所有追问的回答必须引用该机构的人设文件来推导推理链
- 如果用户的问题触及知识边界，诚实地说"这个维度我没有足够的数据"而非编造

---

## 追问类型及其处理

### 类型 1：追问某个机构的推理

**用户输入模式：** "红杉为什么在市场维度打8分？" / "Benchmark 为什么对平台这么谨慎？"

**处理方法：**
1. 加载该机构的人设文件 `references/[机构名].md`
2. 结合该机构的 核心信条 + 核心关注维度 + 典型框架 进行推理
3. 输出该机构在该维度上的完整推理链

**输出格式：**
```markdown
### [机构名]：[维度名]推理链

1. [推理步骤 1 - 基于该机构的信条]
2. [推理步骤 2 - 基于该机构的框架]
3. [推理步骤 3 - 基于该机构的风格/偏好]
4. → 得出结论：打 [N] 分

**核心假设：** 这个推理依赖于 [具体假设]。如果这个假设不成立，评分会变化 [方向]。
```

### 类型 2：追问某个分歧

**用户输入模式：** "巴菲特和软银在护城河上的分歧具体在哪？"

**处理方法：**
1. 加载两个机构的人设文件
2. 找出他们评估同一个问题时采用的不同框架
3. 对比框架：机构A从什么视角看、机构B从什么视角看
4. 指出分歧的不可调和程度

**输出格式：**
```markdown
### 分歧深度分析：[议题]

**机构A（[机构名]）的视角：**
- 框架：[机构A 使用的框架]
- 核心假设：[假设 X]
- 推导：[框架+假设→结论]
- → 结论：[立场]

**机构B（[机构名]）的视角：**
- 框架：[机构B 使用的框架]
- 核心假设：[假设 Y]
- 推导：[框架+假设→结论]
- → 结论：[立场]

**分歧本质：**
- 不可调和程度：[完全可以调和 / 可以调和但很难 / 根本不可调和]
- 原因：[分析为什么这两个视角难以统一]
- 判断建议：如果你更认同 [某种哲学]，你会站在 [机构A] 这边
```

### 类型 3：压力测试

**用户输入模式：** "如果市场增速放缓到10%，谁的判断还站得住？"

**处理方法：**
1. 逐一检查六家机构的核心判断
2. 在新假设下，重新评估每家机构的立场是否变化
3. 输出更新后的立场表

**输出格式：**
```markdown
### 压力测试：[新假设]

| 机构 | 原立场 | 新假设下立场 | 是否变化 | 原因 |
|------|-------|------------|---------|------|
| [机构] | [原立场] | [新立场] | 是/否 | [原因] |

**最有韧性的判断：** [机构名] 的判断在压力测试下变化最小，因为 [原因]
**最脆弱判断：** [机构名] 的判断在压力测试下可能完全翻转，因为 [原因]
```

---

### 类型 4：追加分析维度

**用户输入模式：** "帮我分析一下政策监管对这个赛道的影响"

**处理方法：**
1. 用通用分析引擎的方法做新维度分析
2. 让六家机构基于其人设对新维度进行独立评估
3. 追加到辩论对比表中
4. 更新打分卡

---

### 类型 5：参考历史案例

**用户输入模式：** "这个赛道和之前分析的AI Agent赛道有什么异同？"

**处理方法：**
1. 从 `memory/case-library/` 中加载指定案例
2. 对比两个赛道的各维度评分
3. 找出过去案例中机构判断和实际结果的关系（如果有结果反馈）
4. 输出对比分析
