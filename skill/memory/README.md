# 记忆系统 - Memory System

## 为什么需要记忆系统

每次分析一个赛道，你都在积累关于赛道分析的知识。但如果没有记忆系统，每次都是从零开始。
记忆系统让 Codex 在使用这个 skill 时能：
1. **记住过去的分析** — 引用历史案例进行对比
2. **学习用户的偏好** — 逐渐校准到用户的分析风格
3. **积累跨赛道洞察** — 发现重复出现的模式和信号

## 文件结构

```
memory/
├── README.md                   ← 本文件
├── user-profile.json           ← 用户画像（偏好、权重、历史模式）
├── case-library/
│   └── index.md                ← 案例库索引
└── insights.md                 ← 跨赛道洞察积累
```

## 工作流整合

每次执行赛道分析时，Codex 必须按以下流程使用记忆系统：

**分析前（加载记忆）：**
1. 读取 `user-profile.json`，了解用户的权重偏好、历史机构信任度
2. 读取 `case-library/index.md`，检查是否有相似的已分析赛道
3. 读取 `insights.md`，了解已有的跨赛道模式

**分析中（应用记忆）：**
1. 如果找到相似赛道，标注"这个赛道与 [历史赛道] 类似，当时 [结果]"
2. 使用用户配置的权重计算打分卡（替代默认权重）
3. 引用用户历史信任的机构观点做特别标注

**分析后（保存记忆 — 需用户确认）：**
1. 询问用户："是否保存这次分析到案例库？"
2. 如果用户同意，保存到 `case-library/[日期]-[赛道名].md`
3. 更新 `case-library/index.md`
4. 询问用户："这次分析是否有想记录的个人洞见？"
5. 如果有，更新 `insights.md`
